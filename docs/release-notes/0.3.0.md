# Tap 0.3.0 Release Notes

Tap 0.3.0 adds Tailscale as a first-class tunnel provider alongside Cloudflare, makes private (tailnet-only) exposure the safe default, and introduces a QR-code page for opening public URLs on a phone in one tap. The release also reorganizes the inspector's settings under a single Config tab, extends saved tunnel profiles to cover Tailscale, and adds a security warning whenever a tap is publicly exposed without auth.

## Highlights

- **Tailscale Funnel and Serve** — Tap can now route traffic through Tailscale. By default it uses `tailscale serve` (reachable only from your tailnet); switch to `tailscale funnel` (public internet) when you actually need it.
- **Three Tailscale daemon modes** — reuse the host's existing `tailscaled`, spawn a per-session userspace daemon from an auth key, or run `tailscale/tailscale` in Docker (works on macOS without a host install).
- **Tailnet-only is the new default** — `tap run --tailscale` is private out of the box; `--tailscale-public` opts into public funnel. Aspire users get the matching `WithTailscaleServe(...)` (default) and `WithTailscaleFunnel(...)` (opt-in) extensions.
- **Public-exposure warning** — whenever a tap is reachable from the public internet (any Cloudflare tunnel or Tailscale Funnel), the inspector shows a warning banner reminding you to pair it with auth. The Tunnel detail dialog also surfaces a `public` / `tailnet-only` badge.
- **QR code page** — a new "QR" tab in the inspector renders a scannable QR for each public URL, so you can open it on your phone without typing the hostname. The CLI's run banner includes a "Open on phone" deep link to that page.
- **Config tab consolidation** — the old "Cloudflare" tab is now "Config" and groups three sub-tabs: Tunnel profiles (now Tailscale-aware), Cloudflare guide, and a new Tailscale guide with prerequisites (HTTPS enable, ACL nodeAttrs, auth-key generation) and mode comparisons.
- **Live tunnel status panel** — the Tunnel dialog for a Tailscale tap shows live daemon state (backend, MagicDNS name, tailnet, IPs, version) and the current `serve` / `funnel` rules on the node.
- **Sample AppHost provider filter** — `dotnet run --project samples/Sample.AppHost -- --scenarios tailscale|cloudflare|all` runs only the requested provider's scenarios; the sample now demonstrates eight tunnel configurations across both providers.

## What Changed

- Added the `Tailscale` tunnel mode end-to-end: Aspire AppHost extensions, CLI runtime, Tap.Server inspector endpoints, React UI, and tunnel profile storage.
- Aspire users can attach Tailscale via `tap.WithTailscaleServe(...)` (private, default) or `tap.WithTailscaleFunnel(...)` (public, opt-in), with `WithSystemDaemon()` / `WithEphemeralDaemon(authKey)` and `WithFunnelPort(443|8443|10000)` to configure further. Pass `hostMode: TailscaleHostMode.Docker` to run the daemon in a `tailscale/tailscale` container instead of as a host process.
- The CLI gains `--tailscale`, `--tailscale-public`, `--tailscale-port`, `--tailscale-authkey` (env: `TAILSCALE_AUTHKEY`), `--tailscale-login-server` (for Headscale), and `--tailscale-system` (force system daemon when `TAILSCALE_AUTHKEY` is exported globally).
- The shared `--docker` flag now also drives Tailscale: with `--tailscale --docker`, the CLI runs `tailscale/tailscale` in a container — handy on macOS where the GUI Tailscale client doesn't expose a `tailscaled` binary.
- Tunnel profiles saved under `~/.tap/tunnels/` now support Tailscale: daemon mode (system/ephemeral), auth key, login server, funnel port, and a public/tailnet-only toggle. The inspector profile editor exposes all of these fields.
- The inspector picks the right branding per provider — Tailscale icon and Tailscale-blue accent for Tailscale taps, Cloudflare logo and orange accent for Cloudflare taps. The flow diagram and 502 error page reflect the active provider.
- The 502 page now distinguishes Tailscale Serve, Tailscale Funnel, and Cloudflare flows so an upstream-down moment shows you the right chain.
- Both Cloudflare and Tailscale public tunnels mark their ingress entries as "public exposure" so the inspector's warning banner applies uniformly across providers.
- The QR page polls `/api/config` while a hostname is still resolving (quick tunnels, fresh Tailscale nodes), so the QR appears automatically without a manual refresh.
- The CLI run banner includes a clickable "Open on phone" link to `http://localhost:<uiPort>/#qr` whenever a public URL is available.
- Pre-warmed Tailscale TLS cert files are now written into the system temp directory instead of the AppHost / CLI working directory, so cert files no longer end up in your project tree. Stray `*.ts.net.crt` / `*.ts.net.key` files are also gitignored.
- Updated README and ARCHITECTURE to document Tailscale setup (HTTPS enable, ACL `funnel` nodeAttrs, auth-key generation), the new CLI flags and env vars, and the public-exposure security guidance.
- The sample Aspire AppHost gains three Tailscale scenarios (system daemon, ephemeral userspace, ephemeral Docker) gated on `Tailscale:UseSystem`, `Tailscale:AuthKey`, and `Tailscale:UseDocker` user-secrets respectively.

## Compatibility

- No breaking changes to existing Cloudflare APIs or CLI flags. All previous `WithCloudflareTunnel`, `WithQuickTunnel`, `WithExistingTunnel`, `WithApiManagedTunnel`, `WithDynamicHostname`, and `WithTunnel` calls keep their semantics.
- The inspector's old "Cloudflare" tab is now "Config". The old URL hashes (`#cloudflare`, `#docs`) still resolve to the new tab, so existing bookmarks keep working.
- Tailscale features require the `tailscale` CLI on PATH for host modes (skip when running Tailscale entirely in Docker). Funnel additionally requires HTTPS Certificates enabled in your tailnet and the `funnel` ACL capability granted on the node's tags. `tailscale serve` (the new default) only needs HTTPS Certificates.
- Tailscale ephemeral mode requires either `tailscaled` on the host (Process mode, e.g. `brew install tailscale`) or Docker (Container mode). The macOS App Store / GUI Tailscale client only ships a CLI shim — use Docker mode there. Ephemeral process mode is not yet supported on Windows; pair the auth key with `--docker` (CLI) or `hostMode: TailscaleHostMode.Docker` (AppHost) instead.
- Saved tunnel profiles created in earlier versions continue to work unchanged. New Tailscale-specific fields default sensibly when missing.
- Public tunnels (Cloudflare any mode, Tailscale Funnel) now display a warning banner in the inspector reminding you to pair the proxy with auth (`WithHeaderAuth`, `WithIpAllowList`, `WithCountryAllowList`, `WithOidcAuth`, or the matching CLI flags). This is purely advisory — no behavior change for already-configured taps.
