# Tap 0.7.0 Release Notes

Tap 0.7.0 makes a workspace usable by AI coding agents — with a harder guarantee than any
human user gets: an agent can discover what exists, send fully-authenticated requests, fire
ad-hoc calls, and run test sets **without ever needing, seeing, or holding a credential**.

The workspace already owned the base URLs, environments, variables, and auth. This release
adds the agent-shaped doors onto that ownership: machine-readable discovery, a redacted JSON
mode, dynamic requests with a credential-exfiltration guard, the same surface served as MCP
tools from two hosts, and a per-collection switch to opt out of all of it. As always, every
door leads to the same engine — a verdict an agent reads and a verdict on the Testing tab are
one computation.

## Highlights

- **Agent-friendly CLI** — new `list [kind]` and `describe <request>` discovery commands, and
  `--json` on `send`, `call`, and `test`: one parseable, secret-redacted document on stdout,
  progress and errors on stderr, same exit codes a pipeline branches on.
- **Dynamic requests: `call`** — `tap-studio call GET /users/42 -c demo` sends a request that
  has no file, *through* a collection, inheriting its baseUrl, default headers, variables, and
  auth. URLs must stay relative to the collection — checked before render and again after
  variable expansion, because a request that carries a collection's credentials must not be
  aimable anywhere else. `--allow-any-url` is the explicit opt-out.
- **Secret redaction, everywhere agents read** — the renderer builds a redactor from every
  secret that went into a render (secret-flagged variables, provider-resolved values, minted
  tokens) and scrubs the serialized output, including JSON-escaped variants. Discovery reports
  auth profiles as name + type only.
- **MCP servers, one implementation, two hosts** — `tap-studio mcp` serves
  `workspace_inventory` / `describe_request` / `send_request` / `call_request` / `run_test`
  over stdio (workspace re-read per call, headless auth). The running Studio serves the same
  tools at `/mcp` over its live workspace — and over the user's interactive token cache, so
  **PKCE-authed requests work for an agent** after one browser sign-in, with the token never
  leaving the Studio process.
- **Per-collection agent control** — `agent: false` in `_collection.md` (or the **Agent
  access** switch in the collection editor) fences a collection off: its requests vanish from
  agent discovery and the agent surfaces refuse it with `E_AGENT_ACCESS_DISABLED`. The
  structured form `agent: { enabled: false }` is the extension point for finer-grained
  control later. Humans in the Studio and plain CLI runs are unaffected.
- **Two shippable skills** — `.claude/skills/tap-studio` teaches an agent to *operate* a
  workspace (discover → describe → call, exit codes, auth rules); `.claude/skills/tap-author`
  teaches it to *author* one (full per-kind file spec, assertion + extraction grammar,
  templates, and the write → lint → describe → send → test loop). Both are self-contained and
  written to be copied into your own repos.
- **One-command setup: `tap-studio agent init`** — `--env claude|codex|copilot|opencode`,
  `--scope project|user`, `--skills`/`--mcp`. Installs the skills (embedded in the tool, so a
  tool update + re-run refreshes them) and registers the MCP server in each environment's own
  config format — `.mcp.json`, `.codex/config.toml`, `.vscode/mcp.json`, `opencode.json` —
  idempotently, with a managed guide block in `AGENTS.md`/`copilot-instructions.md` for the
  environments that read instructions instead of skills. Run it with **no `--env`** on a
  terminal and it becomes a wizard: it detects which environments the machine runs (CLIs on
  PATH, config directories, project markers) and preselects them; headless callers keep the
  usage error instead of a hanging prompt.

## Also in this release

- **Downward workspace discovery** — when no ancestor of the working directory has a `tap.md`,
  every command now takes the first workspace *beneath* it (shallowest, then alphabetical, to
  a bounded depth, skipping dependency folders). Standing at a repo root whose workspace lives
  in `samples/` or `api/tap` just works.
- **`gh`-CLI auth mints headlessly** — a `github` auth profile in `gh-cli` mode now shells out
  to `gh auth token` in the CLI and MCP servers, by the same rule that admits `azure-cli`. A
  dynamic `call` through a GitHub collection works with nothing but a signed-in `gh`.
- `send`/`call` share one runner code path with test steps — an ad-hoc call, a saved send, and
  a test step cannot behave differently.
- `test --json` prints the same run-report envelope the `--output json` file report writes.
- Workspace discovery keeps working on a partially-broken workspace: files that parse are
  listed, parse errors become warnings on stderr.
- New shared `Tap.Studio.Mcp` library carries the MCP tool contracts so the stdio host and the
  Studio host can never drift apart.
