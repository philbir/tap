# Tap 0.4.0 Release Notes

Tap 0.4.0 makes streaming protocols first-class. WebSocket upgrades and Server-Sent Events flow through the same proxy as regular HTTP traffic, and the inspector UI gains live, direction-tagged frame and event timelines so you can watch messages append in real time while a connection is open. The release also adds a sample WebSocket endpoint and client card to the demo app, animates the open-WebSocket cue across the UI, and lets the public-exposure warning be dismissed for the session.

## Highlights

- **End-to-end WebSocket support** — Tap intercepts WebSocket upgrade requests, terminates them at the proxy, and re-originates a matching `ClientWebSocket` against the upstream while pumping frames in both directions. Subprotocols and forwardable request headers are preserved, so authenticated WebSocket APIs work through the tunnel.
- **Live SSE + WS message timelines in the inspector** — every `text/event-stream` event and every WebSocket frame (text, binary, close) appears in dedicated **SSE** and **WS** tabs in the request detail view, with timestamps, direction (`↑ client` / `↓ server`), payload, size, and close-code, appended live as they arrive.
- **Animated "live" indicator** — open WebSocket records pulse on the request list badge and on the **WS** tab title so you can spot active connections at a glance. Honors `prefers-reduced-motion`.
- **Sample `/ws` endpoint and client card** — `Sample.Api` now exposes a WebSocket echo + heartbeat endpoint, and the demo client renders a card with connect/disconnect controls and an inline frame log alongside the existing `/sse` card.
- **Dismissable public-exposure warning** — the orange "Public exposure" banner in the inspector now has a close button that hides it for the rest of the browser session (persisted in `sessionStorage`).
- **Collapsed-by-default headers in stream tabs** — the SSE and WS tabs now show the relevant request/response headers in a collapsed panel above the timeline so the live frames stay front and center.

## What Changed

### Server

- New `WebSocketProxy` ([`src/Tap.Server/WebSocketProxy.cs`](../../src/Tap.Server/WebSocketProxy.cs)) accepts the upgrade with `HttpContext.WebSockets.AcceptWebSocketAsync`, resolves the upstream from the ingress array (Host-header match with a wildcard fallback), opens a `ClientWebSocket` against `ws(s)://` (auto-derived from the upstream's `http(s)://` scheme), forwards subprotocols and non-hop-by-hop request headers, and pumps frames bidirectionally with a 16 KB buffer. Each completed text/binary message and every `Close` frame is recorded.
- `CaptureMiddleware` now branches on `HttpContext.WebSockets.IsWebSocketRequest` and delegates to `WebSocketProxy`. The proxy branch in `TapInspectorHost` calls `app.UseWebSockets()` ahead of capture and registers `InspectorIngressEntry[]` as a singleton so the middleware can resolve upstreams.
- `RequestRecord` gains `IsWebSocket` and `WebSocketMessages: List<WebSocketMessage>`, where each `WebSocketMessage` carries `direction`, `type`, `text`/`base64`, `size`, `truncated`, and (for close frames) `closeStatus`/`closeDescription`. The 1 MB capture cap is enforced per message.
- `IRequestStore` / `InMemoryRequestStore` add `AppendWebSocketMessage(record, message)` and broadcast a new `WebSocketStreamEvent` to subscribers.
- `/api/stream` now emits a named `event: ws` line for each WebSocket frame in addition to the existing default snapshots and named `event: sse` lines.

### Sample app

- `Sample.Api` adds `/ws`: accepts WebSocket upgrades, echoes incoming text/binary frames, and emits a periodic JSON `tick` heartbeat (interval configurable via the `interval` query string). The endpoint catalog advertises it with `IsWebSocket: true`.
- `Sample.Client`'s `EndpointCard` learned a third call mode for WebSocket endpoints — connect/disconnect/reconnect controls, an inline text-frame composer, and a frame log tagged with direction. Existing standard and SSE flows are unchanged.

### Inspector UI

- New `WS` tab in the request detail view with a frame timeline (per-frame direction badge, type, timestamp, size, JSON pretty-print, base64 preview for binary, close-code rendering). Direction filter (`All` / `Client` / `Server`) and auto-scroll are exposed in the panel header.
- Selecting a WebSocket record auto-jumps to the **WS** tab; selecting an SSE/regular record keeps the existing default.
- Request list shows a `WS · N` badge per record. While the socket is open the badge breathes with a soft green halo + pulsing dot; once closed the badge goes muted/static. Same animation on the **WS** tab title.
- `useRequestStream` ingests the new named `ws` SSE messages and merges them into the matching record, mirroring the existing `sse` handling.
- `HeadersPanel` accepts an optional `defaultExpanded` prop so the SSE and WS tabs render headers collapsed by default.
- The public-exposure banner is dismissable via a close button; the dismissal is stored in `sessionStorage` (`tap.publicExposureDismissed`) so it stays hidden for the tab session and reappears on the next reload or new tab.

### Docs

- README adds a "Streaming protocols" use-case row, calls out the live WS/SSE timelines in the quick-start narrative and `Tap.Server` package description.
- `docs/ARCHITECTURE.md` documents the WebSocket proxy + SSE parser, expands the capture-model table with SSE event and WebSocket frame field groups, and notes that `/api/stream` carries `sse` / `ws` named events for live UI rendering.
- The docs-site landing page gains a "Live streaming protocols" feature card.
- `CLAUDE.md` updated with the new request-flow notes (`UseWebSockets` ordering, `WebSocketProxy`, named `sse`/`ws` events, **WS** tab).

## Compatibility

- No breaking changes to existing APIs. All previous `AddTap`, `WithTap`, `WithTunnel`, Cloudflare and Tailscale extensions, and CLI flags keep their semantics. WebSocket support is automatic for any `WithTap`-attached upstream — no new opt-in flag.
- HTTP request capture is unchanged for non-streaming traffic. The 1 MB body cap still applies; for WebSockets the cap is enforced per message and oversized payloads are flagged `truncated`.
- The `/api/stream` channel adds a new named `ws` event type. Older clients that only listen to default `data:` snapshots and named `sse` events keep working — they will simply ignore `event: ws` lines.
- `RequestRecord` JSON now includes `isWebSocket` and `webSocketMessages` fields. Both default to absent / `[]` for non-WebSocket records, so existing consumers parsing record JSON keep working.
- The dismissable public-exposure banner is purely a UI affordance and respects `sessionStorage`; nothing about which taps are flagged as public has changed.
- `prefers-reduced-motion: reduce` disables the WebSocket pulse animations and falls back to a static high-contrast green tint.
