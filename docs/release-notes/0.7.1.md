# Tap 0.7.1 Release Notes

A patch release. The reason it exists is the desktop updater: **0.7.0's update manifest points
at a file that release never carried**, so the in-app "Install & restart" fails after the
download. Everything else here is Studio polish that landed alongside the fix.

## The updater fix

Tauri's action version-stamps the bundle names it uploads. The workflow that composes
`latest.json` hardcoded one of those names instead, so the manifest it published named an asset
that did not exist. The signature check passed — signatures are over content, not URLs — and the
install then 404'd.

Three changes, all in `.github/workflows/desktop.yml`:

- **Every download URL is now derived, never written.** `<name>.sig` always sits beside
  `<name>` on the release, so the manifest takes the name from the signature asset that was
  actually uploaded.
- **Each candidate URL is HEAD-checked before it goes in the manifest.** A release can carry
  more than one signature matching a pattern (0.7.0 still carries the leftover hand-named macOS
  one), so candidates are ranked by whether they resolve rather than by glob order. Discovering
  a bad URL in CI beats discovering it after a user clicks Install.
- **An empty manifest is now a failed build.** Publishing zero platforms used to be silent.

The step that re-uploaded the macOS signature under a hand-written name is gone; `tauri-action`
already uploads every `.sig` next to its artifact.

> **Updating from 0.7.0:** the 0.7.0 in-app updater cannot reach this release — it fails on
> 0.7.0's own manifest before it sees 0.7.1. Install 0.7.1 from the
> [downloads](https://philbir.github.io/tap/#studio-install) once, and in-app updates work from
> there on.

## Studio

- **Delete, from wherever you're looking at the thing.** Test sets and flows have the
  right-click menu requests already had, and every editor's Source tab carries a Delete for the
  file it is showing — request, collection, auth profile, environment, test set, flow, and
  `.http` file. A collection deletes its directory (deleting only `_collection.tap` would orphan
  the requests inside it); a `.http` row deletes the one file it really is. `workspace.tap` has
  no Delete: that file *is* the workspace.
- **A deleted file leaves the UI immediately.** `DELETE /api/workspace/files`, `/folders`, and
  `/api/collections/{slug}` now reload the workspace model before returning, the way `/move`
  already did. The client refetches the instant a delete returns, and used to get a model that
  still listed what it had just deleted.
- **The brand mark is now the app menu** — which build is running, plus GitHub and the docs.
  The version comes from the server rather than the bundle (`/api/workspace` reports it), so the
  number you quote in a bug report is the one the process reports for itself.
- **One ⋯ per tree row in the desktop app.** The row's context-menu trigger rendered as two
  overlapping ellipses under WKWebView, where the scrollbar gutter is reserved differently than
  in Chromium.
- **Variables panel holds its frame.** The dialog no longer resizes and re-centres under the
  cursor on every cascade click; the two columns scroll inside a pinned frame instead. The
  provider bindings moved into the title bar, and the tier that lists machine variables is
  labelled SYSTEM again.

## Upgrading

Nothing to migrate — no workspace-format, CLI, or API changes. `.md` workspace files still load
with a `W_LEGACY_EXTENSION` warning for the whole 0.7.x line; `tap-studio migrate` converts a
workspace when you're ready. Removal is still targeted at 0.8.0.
