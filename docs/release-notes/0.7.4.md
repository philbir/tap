# Tap 0.7.4 Release Notes

0.7.3 taught the body editor to write a SOAP envelope. This release is about not having to:
point Studio at a service's own description and let it write them for you. Along the way the
tab that reads those descriptions stopped being about one format, and the response viewer
learned to show XML the way it shows JSON.

## Import from WSDL

**Import from WSDL** joins **Import from OpenAPI**. Upload a `.wsdl` or fetch a URL, pick the
operations, and each one becomes a request with the envelope already in it — built from the
service's own schema, with the `SOAPAction` and content type its binding calls for.

The body is not a stub. The generator walks the inlined XSD and writes what the operation
actually accepts: nested complex types, an enumerated type's first value (a value the service
definitely takes, which no synthesized placeholder can claim), required attributes, and a
comment naming the arms of an `xsd:choice` it did not take. A type that contains itself stops
at a bounded depth rather than unrolling forever. Everything it writes is deterministic — no
timestamps, no fresh GUIDs — because the generated body is hashed into the collection's lock,
and a generator that answered differently each run would report every request as edited.

`document/literal` and `rpc/literal` are both handled, including the namespace rule that
decides whether an element is qualified. That rule is the difference between a payload a
service accepts and one it rejects with an empty fault, so it is read per declaration —
`form`, then the schema's `elementFormDefault` — rather than assumed.

**Both SOAP versions, once.** A .NET service almost always binds the same portType over SOAP
1.1 and 1.2, and those are genuinely two different requests: different envelope namespace,
different content type, and 1.2 carries the action on the media type instead of in a
`SOAPAction` header. Importing both writes two of every request, so the picker groups by port,
flags the pair, and pre-selects one of them.

**WS-Security UsernameToken**, optionally. Tick the box and every envelope gets a
`<wsse:Security>` header with the credentials declared as collection variables — one place to
fill them in, the password marked secret so it never lands in the file as plain text. It is
pre-ticked when a policy in the description asks for one. It is the only header Tap authors,
because it is the one nearly every legacy service wants; anything else you write by hand
survives untouched, which was already true of the body editor.

The envelope Tap generates is byte-for-byte what the SOAP body editor produces from the same
parts. Opening a generated request and saving it is a no-op in the diff — which is the
difference between an import you can trust and one that rewrites every file the first time you
look at it.

**What it will not do is fetch a second document.** `xsd:import` and `wsdl:import` carry a
location the *document* chooses, and following one would let a description you fetched fan a
single approved request out into requests to hostnames named inside the file. The same rule
already governs OpenAPI `$ref` resolution. Those types generate as empty elements with a
diagnostic saying so and pointing at the self-contained form — WCF publishes one at
`?singleWsdl`. WSDL 2.0 is refused by name rather than as "not a WSDL", and so is an `.xsd`
pointed at the importer by mistake, which is the more common slip of the two.

## The Schema tab

A collection's **OpenAPI** tab is now **Schema**, and it covers every description format —
OpenAPI today, WSDL as of this release, GraphQL when it arrives. Linked collections show one
card per description with its source, its badges, and what it tracks; re-sync appears on the
formats that have it. Adding a format is an entry in one registry and a normalizer, not
another tab and another branch.

## Reading the response

**Formatted or raw.** JSON has always been re-indented for display; XML now is too, and a
toggle beside the status pill switches to the exact bytes the server sent. That is the view
you want precisely when the whitespace is the question — a signature over a canonical body, a
diff against what curl printed, an "is this really all one line?" check. The choice sticks to
the tab, so a re-send keeps it. Both formatters are total: anything that doesn't parse comes
back untouched, because a body that failed to parse is the one you most need to read verbatim.
XML goes through `DOMParser` rather than a tag-matching pass, so namespaced payloads, SOAP
faults, CDATA and comments all survive the trip.

**Downloading a binary response works.** A body Studio could only describe reached the panel
as `[binary N bytes — …]` and nothing else — the bytes were on the server's side of the wire
and, if the response was small enough to fit inline, nowhere at all. So **Download response**
sat there offering a file it could not produce. Such a body is now retained whatever its size,
because the spool is the only place a download could read it from.

Two smaller corrections came with it: the menu says **Download full response** only when the
panel is actually showing a prefix — a retained body also backs a small binary one, and calling
that "full" promises a difference that isn't there — and a result with no body at all now says
so instead of leaving two items greyed out with no explanation.

## Try it

The sample workspace gains a **Weather** collection under `collections/soap/`, generated by the
importer against a real SOAP service that now ships in `Demo.Api` — `GetWeather`,
`ListStations`, and a `Boom` that always faults, over both SOAP versions, with a self-contained
WSDL at `/demo/soap/weather.asmx?wsdl`. The service echoes a `UsernameToken` back so the
header option visibly does something.

`tests/soap.test.tap` runs all three, fault included. Its assertions go through `local-name()`,
with a note on why: a SOAP response is namespaced and XPath 1.0 has no notion of a default
namespace, so `/Envelope/Body` matches nothing at all. That is the first thing anyone writing
SOAP assertions gets wrong.

## Upgrading

Nothing to migrate. No workspace-format or CLI breaking changes — a generated SOAP request is
an ordinary `.req.tap` with an XML body, and the import writes a `_wsdl.lock.json` sidecar
beside the collection that the loader never reads. Deleting it loses the recorded provenance
and nothing else.

New endpoints, all Studio-internal: `POST /api/wsdl/documents`, `POST /api/wsdl/documents/fetch`,
`POST /api/collections/import/wsdl`, and `GET /api/collections/{slug}/wsdl`. Nothing existing
changed shape.

Re-sync remains OpenAPI-only. The WSDL lock records the upstream and generated hashes a differ
would need, so it is a feature to add rather than a format to change.

`.md` workspace files still load with a `W_LEGACY_EXTENSION` warning for the whole 0.7.x line;
`tap-studio migrate` converts a workspace when you're ready. Removal is still targeted at 0.8.0.
