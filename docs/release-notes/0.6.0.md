# Tap 0.6.0 Release Notes

Tap 0.6.0 makes a workspace testable — first from the Studio UI, then from a terminal, then
from CI, with the same engine answering all three.

Two new file kinds turn a folder of requests into a suite: a **flow** runs requests in order
and carries values from one response into the next, and a **test set** groups checks that each
run one request or one flow. A new **Testing** tab authors and runs them. A new **`tap-studio`
.NET tool** runs them headlessly and reports JUnit, TRX, JSON, or Markdown with exit codes a
pipeline can branch on.

The thing that makes this worth having: the CLI and the UI are the *same code*. A verdict from
a pull-request check and a verdict from the Testing tab are one computation over one set of
files, not two implementations that drift.

## Highlights

- **Flows (`*.flow.md`)** — an ordered list of steps, each naming an existing request, each
  able to **extract** values out of its response for the steps below. Extract from a JSONPath,
  an XPath, a header, the status, the duration, the whole body, or a regex capture group. A
  missing value fails the step rather than silently binding nothing.
- **Test sets (`*.test.md`)** — set-scoped variables plus a list of tests, each running one
  request or one whole flow, with extra assertions layered on the target's own. `onFailure`
  decides whether a failure stops the set or lets the rest report.
- **Testing tab in the Studio** — a step composer for flows (variable ← source, read left to
  right), a runner for test sets, and a results pane that streams each step as it lands with
  its assertions, bound values, and response body.
- **`tap-studio` CLI** — `dotnet tool install -g Tap.Studio.Cli`, then
  `tap-studio test "Demo API smoke"`. Also `send`, `lint`, and `vars`.
- **CI reports and exit codes** — `--output junit|trx|json|markdown`, and exit `1` for a failed test
  versus `2`/`3`/`4` for usage, workspace, and auth problems, so a red build caused by an API
  is distinguishable from one caused by a broken runner.
- **Selection by tag and by name** — `--tag smoke` runs every test set and flow carrying it
  (repeats union), `--filter` narrows the tests inside a set. A selection that matches nothing
  is an error, never a green run over zero tests — the failure mode that leaves a pipeline
  passing forever while testing nothing.
- **Headless auth that refuses rather than hangs** — client_credentials, ROPC, and `az` are
  minted without a human; an interactive grant fails immediately with the profile named and the
  alternatives spelled out. The developer token cache is ignored unless `--use-cached-tokens`.

## What changed

### Workspace format

- Two new kinds in [§10 and §11](../workspace-format.md): `flow` (`*.flow.md`) and `test`
  (`*.test.md`), both living in `tests/`. New error codes `E_FLOW_INVALID` and
  `E_TEST_INVALID`; a malformed assertion inside a step keeps its own `E_ASSERT_INVALID` with
  the step's position prefixed.
- Extraction (§10.3) reuses the assertion extractor vocabulary, plus `regex` as a source in
  its own right so it can bind a capture group. `default:` and `required: false` mark a value
  as genuinely optional.
- Variable precedence for a run (§10.5): test-set vars < the test entry's vars < flow vars <
  values bound by `extract:` < the step's own vars. Extraction beats the static tiers on
  purpose — a flow whose bound id could be overridden by its caller is no longer a flow.
- `steps:` / `tests:` are optional. The editor writes frontmatter before the first entry
  exists, and a file you just created has to still load.

### Engine

- **New `Tap.Execution` package** — the execution engine, extracted out of `Tap.Studio`: HTTP
  transport and redirect policy, body capture, assertion running, value extraction, and the
  sequential run engine. No ASP.NET Core, no Git, no UI.
- `AssertEvaluator`'s private extractor became a public `ResponseReader` shared with
  `ValueExtractor`, so an assertion and an extraction can never disagree about what
  `$.order.id` means.
- The render path became `RequestPipeline`, behind `IWorkspaceHost` + `IAuthTokenSource`.
  `WorkspaceService` implements the former and delegates; its public surface is unchanged, so
  the Studio's endpoints were untouched.
- `Tap.Execution/Contracts/` holds the result records both front ends read. The Studio
  serializes them straight onto its SSE stream; the CLI renders them to JUnit. They are a
  shared public API — a change there is breaking for both.

### CLI

- **New `Tap.Studio.Cli` package**, tool command `tap-studio`. Separate from the existing `Tap`
  tunnel/inspector tool — different product, different command, installable side by side.
- Workspace discovery walks up to the nearest `tap.md`. Targets resolve by path, by `name:`,
  or by filename stem; an ambiguous name lists the candidates instead of guessing.
- `--var name=value` and `--var-file` (`.env` or JSON) land in the run's override tier, above
  every file scope.
- `--output markdown` writes a report for people rather than parsers — verdict, then failures
  in full, then a table per target, with passing targets collapsed into a `<details>`. Made for
  a GitHub job summary (`cat summary.md >> "$GITHUB_STEP_SUMMARY"`).
- `--tag` replaces the name argument rather than narrowing it — passing both is an error rather
  than a precedence rule to memorise. A tagged run writes one JUnit `<testsuite>` per target;
  `--output json` is always an envelope so a script needn't branch on the target count.
- Colour is suppressed on `NO_COLOR` or a redirected stdout; results print incrementally rather
  than as a redrawn tree, because a CI log is not a terminal.

### Studio

- New Testing view in the sidebar, `TestSetEditor` and `FlowEditor`, an extraction table, and a
  streamed run panel. Test sets and flows are creatable from the + dialog.
- `POST /api/tests/run` streams `start` / `step` / `entry` / `done`; `/api/flows` and
  `/api/test-sets` follow the existing list / detail / typed-spec-save shape.

### Repo

- `.github/workflows/workspace-tests.yml` lints the sample workspace and runs its test set on
  every push, publishing the JUnit report — and doubles as the worked CI example the docs
  point at.
- `.config/dotnet-tools.json` pins the CLI for contributors.
- 295 tests, up from 184: flow and test-set parsers, emitter round-trips, the extractor, run-bag
  precedence, entry selection, and the CLI's variable inputs, target resolution, tag selection,
  workspace discovery, and every report writer.

## Upgrading

Nothing to do. The new file kinds are additive — a workspace without a `tests/` folder behaves
exactly as before, and older Tap binaries ignore frontmatter keys they don't know.

If you embed `Tap.Studio` types directly, note that the execution internals moved to
`Tap.Execution`: `HttpExecutionHelpers`, `HttpTransport`, `AssertRunner`, `AuthTokenStore`,
`AuthFieldResolver`, `AuthScopeResolver`, `SystemSettingsStore`, the variable providers, and
the run-result DTOs. `WorkspaceService`'s own surface is unchanged.
