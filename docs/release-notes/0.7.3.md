# Tap 0.7.3 Release Notes

A release about the moments where Studio used to hand you a string and wish you luck: a send
that never reached the server, and a body format it had no shape for.

## When the send never lands

A request that dies in transport has no response to show — no status, no headers, nothing to
read. What it had instead was the flattened exception chain, and "The SSL connection could not
be established, see inner exception." is a dead end. It is accurate and it tells you nothing
about which knob fixes it.

The response pane now leads with a reading of the failure: what kind of fault it was
(certificate, DNS, refused connection, timeout, protocol), one sentence in the reader's terms,
and what usually fixes it. The raw message stays, verbatim, underneath — it is the part that
survives being pasted into an issue, so it is kept rather than replaced.

Matching on the message is deliberately loose. The wording comes from the platform and differs
across macOS, Linux, and Windows, so every rule keys on the stable fragment only and the
fallthrough is always the raw message, never a confident wrong guess.

## The certificate, read back

For a certificate failure the card also offers **Diagnose TLS**, which opens the connection
purely to look at it. The validation callback accepts whatever is presented — the point is to
finish the handshake even when the certificate is bad, because a failed send aborts at the
first fault and can only tell you *that* something was wrong, never *which* thing.

The report is split into verdicts and evidence:

- **The checks** — handshake, hostname match, validity period, chain of trust, revocation —
  each get their own traffic light, computed server-side so "trusted" means the same thing to
  the reporter as it did to the sender. They are derived from the platform's chain flags rather
  than re-implemented: the OS already ran the hostname match, wildcards and SANs and all, and a
  second opinion here would only be a second opinion.
- **The chain** is listed leaf-first, each certificate with its common name, SANs, key
  algorithm and size, signature algorithm, and its own errors. That last part is why the cards
  aren't uniformly red: an element's chain status belongs to that element, so the report can
  point at the certificate that is actually wrong.

Where the handshake completed, the negotiated protocol ("TLS 1.3", spelled the way people say
it), cipher suite, and handshake time come back with it.

A **Bad TLS** collection ships in the sample workspace — expired, wrong-host, self-signed,
untrusted-root, and revoked, all against badssl.com's public endpoints — so the card and the
report can be exercised without arranging a broken server of your own.

## SOAP bodies

`SOAP` joins the body modes. You edit the two parts that vary — the operation element and its
inner XML — and the envelope around them is generated.

What it does *not* do is as important: everything the editor doesn't surface is carried through
verbatim. A `<soap:Header>` block (WS-Security, say), extra attributes on the operation element,
a SOAP 1.2 namespace — open a hand-written envelope here, save it back, and the parts that were
never on screen are unchanged. Tap authors 1.1; it recognises 1.2 rather than quietly rewriting
it.

`SOAPAction` is deliberately not part of this editor. It is an HTTP header, its value is a URI
rather than the bare operation name, and services disagree on whether it is required at all — so
it belongs on the **Headers** tab, where you can see what is actually sent. It is in the header
name completions now, along with the two SOAP content types.

## Content-Type stops hiding

The Body tab owns `Content-Type`, which meant the Headers tab — the place you look to find out
what is being sent — didn't show it at all, and typing it there fought with the body mode.

It is now a pinned first row on **Headers**: the name is fixed, the value is editable, and a
badge says where the current value came from — the body mode, or you. Overriding it is one edit
(a charset, a vendor media type), and a reset control puts it back to whatever the body mode
would have chosen. Typing `Content-Type` as an ordinary row folds into the pinned one instead
of producing a duplicate the wire would never carry.

## Fixes and polish

- **Released builds report their real version.** The desktop app and both container images
  always said `0.1.0-local`. The version was never passed to `dotnet publish` in those two
  packaging paths — the tag only reached the Tauri-side files, and those are stamped in a
  later job than the one that publishes the sidecar the app actually talks to. The brand
  menu, `/api/workspace`, and the `tap-studio/<version>` User-Agent all follow that stamp,
  so all three were wrong together. Fixed from this release onward; an already-installed
  0.7.2 keeps its old answer until it updates.
- **The desktop-app pointer shows outside Aspire.** It was gated on an AppHost hosting the
  Studio. Every browser-hosted Studio lives in a tab that dies with its process, so it now
  shows in all of them and hides only inside the desktop app itself.
- **The workspace editor survives a half-finished provider rename.** The default-provider
  picker fed blank and duplicate names straight to Mantine, which throws on a repeated option
  value — so clearing a provider's name field took the whole editor down with an error it
  could not render its way out of.
- **Tab counts are small circular badges**, matching across the request editor and the
  response pane rather than being a bare dimmed number on one of them.

## Upgrading

Nothing to migrate. No workspace-format or CLI breaking changes — SOAP is a body shape the
editor understands, not a new file format, and a `.tap` request stores the envelope as the raw
body it always did.

One API shape did change: `/api/execute/tls-diagnose` now returns richer certificates and
`errors` as `{ code, description }` objects rather than pre-joined strings, alongside the new
`checks`, `protocol`, `cipherSuite`, and `handshakeMs` fields. The endpoint is Studio-internal
and no CLI output depends on it, but anything scripting it directly will see the new shape.

`.md` workspace files still load with a `W_LEGACY_EXTENSION` warning for the whole 0.7.x line;
`tap-studio migrate` converts a workspace when you're ready. Removal is still targeted at 0.8.0.
