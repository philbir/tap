# Tap 0.2.2 Release Notes

Tap 0.2.2 focuses on making tunnels easier to manage from the inspector and safer to expose. The release adds a Cloudflare profile management UI, expands the CLI with browser-friendly commands, introduces Tap-level auth helpers for Aspire integrations, and adds self-contained binary release automation with an installer script.

## Highlights

- The inspector now includes a Cloudflare profile manager for creating, editing, and deleting saved tunnel profiles used by the `tap` CLI.
- Tap exposes REST endpoints for local profile management so the bundled UI can manage profiles without leaving the inspector.
- Aspire apps can now protect tunneled upstream traffic with header, IP, country, JWT, or OIDC auth gates before requests reach the application.
- The CLI adds `tap ui` for opening the profile manager and `tap docs` for jumping straight to the Tap CLI documentation.
- GitHub Releases can now publish self-contained Tap binaries for Linux, macOS, and Windows, with SHA256 checksums and a shell installer for Linux/macOS.

## What Changed

- Added shared tunnel profile types and storage under `Tap.Core`, moving profile persistence out of the CLI-only layer.
- Added `/api/profiles` endpoints in `Tap.Server` for listing, reading, saving, and deleting local tunnel profiles.
- Added the Cloudflare profile management page to the React inspector UI, including profile editing, validation, and tunnel-mode-specific fields.
- Added `tap ui`, which starts the inspector UI without an upstream or tunnel and opens directly to the Cloudflare profile manager.
- Added `tap docs`, plus shared browser-launching support used by CLI commands.
- Added Tap auth extension methods for Aspire: `WithHeaderAuth`, `WithIpAllowList`, `WithCountryAllowList`, `WithJwtAuth`, and `WithOidcAuth`.
- Expanded Tap auth support with JWT bearer validation, required-claim checks, OIDC cookie sign-in, forwarded-header handling for public redirect URLs, and unauthenticated CORS preflight pass-through.
- Hardened the inspector control plane by rejecting unsafe cross-origin browser requests on the UI port.
- Improved proxy capture behavior for streamed responses so flushes and non-seekable response streams are handled more gracefully.
- Added release automation for self-contained CLI binaries and checksums across `linux-x64`, `linux-arm64`, `osx-x64`, `osx-arm64`, and `win-x64`.
- Added `install.sh` for Linux/macOS binary installs with optional version pinning, checksum verification, and a launcher shim.
- Updated the README install section with .NET tool, binary installer, release asset, and `cloudflared` install guidance.
- Expanded the sample app with JWT-protected endpoints and a browser client that signs HS256 tokens when exercising protected tap proxies.

## Compatibility

- No breaking user-facing API changes are expected.
- `Tap.Core` now owns the tunnel profile model and store so profiles can be shared by the CLI and server UI.
- Auth-enabled scenarios add ASP.NET Core OpenID Connect and JWT bearer package dependencies through central package management.
- The inspector UI control plane still binds to localhost by default, but unsafe cross-origin write requests are now rejected.
- The Linux/macOS installer depends on `curl`, `tar`, and either `sha256sum` or `shasum` when checksum verification is available.
